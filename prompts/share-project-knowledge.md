# Share reusable project knowledge

Paste the instructions below into the Codex chat that owns the work. If you want to share only a specific component or workflow, name it when you paste the prompt.

---

Use the work from this chat to share reusable knowledge in my public GitHub repository, [Gliany/agent-skills](https://github.com/Gliany/agent-skills). Publish the reusable code and the instructions someone else needs to use it. Work from the relevant files in this chat's project and include only material I own or have permission to redistribute.

1. **Check what is already published.** Read the latest `main` and check the catalog, filenames, and actual contents for the same capability, even if it has a different name. Compare the sanitized code and instructions separately. If both already exist, report the existing links. If the code exists and the instructions are missing, add the instructions alongside it. Add missing code and companion files when the repository does not already contain them. Preserve unrelated entries and check for conflicts before updating an existing item.
2. **Prepare a clean public copy.** Include only the files needed to use or understand the contribution. Put skills under `skills/<name>/`, standalone tools under `scripts/`, and reusable prompts under `prompts/`. Provide purpose, setup, dependencies, a runnable example with synthetic inputs, and any required companion files and attribution. Use environment variable names and placeholder configuration values where appropriate.
3. **Review the files and the complete diff for personal information.** Check code, comments, examples, filenames, assets, configuration, and commit metadata. Exclude credentials, names and contact details from private work, account and chat identifiers, private URLs, machine paths, transcripts, logs, screenshots, production data, and runtime state. Replace real examples with synthetic ones. Use a GitHub no-reply address if committing locally. Publish a fresh commit with the selected files, keeping source repository history and private working files out of the public repository. Hold back anything that cannot be safely sanitized or cleared for redistribution.
4. **Publish and verify.** Run relevant offline checks. Publish the reviewed files while preserving the public repository's history and existing content. Update its catalog or manifest where applicable. Confirm the commit and the changed files on GitHub. If access or ownership is unclear, finish the clean package and report the specific blocker.
5. **Report what happened.** Link to the existing or newly published files and, for an upload, the verified commit. Summarize what was added, what was already present, and what was held back. Keep private details out of the report.
