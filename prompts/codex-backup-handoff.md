# Codex backup handoff

Copy the instructions below into the Codex chat that owns the work. Fill in any optional fields you already know. Each run covers the named chat and projects. Repeat it for other chats and hosts you want included in the backup.

---

Back up this Codex chat and its associated work so I can recover the source files and continue the project from another machine. Include the actual code and companion files. Use the scope below and keep working through verification.

- Source chat and projects — this chat and the project workspaces it owns, unless I name a narrower scope.
- Private backup destination — a local folder outside the source workspace by default, or an exact private remote I explicitly authorize. If the remote destination is missing, finish and verify the local backup first.
- Public catalog — `Gliany/agent-skills` at `https://github.com/Gliany/agent-skills`. Publish only the reusable files I own or have redistribution rights for and have authorized for this public catalog.

1. **Inventory the source and existing backups.** Identify the actual chat, host, project roots, Git remotes and branches, and available history and attachments. Check prior manifests or backups and the latest public repository tree. Check both destination paths and content hashes before preparing additions. Record identical items as already backed up or published. Compare differences against the current source and destination. If an existing item has a different owner or purpose, choose a distinct path and keep the existing item intact.
2. **Create the private recovery package.** Capture the accessible conversation history through supported reads or exports, a concise handoff with decisions and next steps, and the actual source files. Include relevant `AGENTS.md` and prompts, skills, scripts, dependencies and lockfiles, tests, assets, settings templates, and recoverable attachments. Record the repository URL, branch and commit and capture scoped uncommitted and untracked work needed to reconstruct the working tree. Preserve Git history from repositories where it is available, and state which refs or history were captured. Record setup steps and list any services or credentials that need to be reconnected. Keep secrets, tokens, cookies, API keys and live session databases out of ordinary backups. Keep chat transcripts and private or project-specific files in the approved private destination.
3. **Add missing public items.** Place approved reusable skills and their companions under `skills/<name>/`, standalone tools under `scripts/`, and reusable prompts under `prompts/`. Include the actual source, usage instructions, dependency declarations, licenses and attribution. Use sanitized continuation notes only when they help explain a published item. Review each proposed file and the diff for credentials, chat history, personal data, private paths and logs, runtime state, unrelated project code, and third-party redistribution rights. Skip identical items, add missing items, and update an existing item only when the change belongs to the same item and the public scope covers it. Check the current `main` head before publishing. Preserve Git history and existing content, with no force push. Update the repository’s documentation or manifest if the change affects it.
4. **Verify recovery and publication.** Write a manifest in the private backup with source and backup paths, sizes, hashes, scope, captured commit and working tree state, and exclusions. Reopen files from the destination or restore into a scratch folder and verify the hashes and that the code, configuration templates, dependencies and handoff are present together. Run relevant offline checks without invoking live accounts. If publishing, verify the remote commit and file contents against the approved package. If an upload result is uncertain, reconcile the destination before retrying.
5. **Report the outcome.** Give me the private backup path, recorded coverage and restore check, and any public paths and verified commit link. List items already present, newly added, skipped or blocked. Name any unavailable chats, hosts, attachments, history ranges, settings or repository refs. A chat export and project snapshot are recovery materials. Claim a complete Codex restore only for the scope you actually restored and verified.
